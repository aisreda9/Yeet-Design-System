# Yeet Design System

Базовая спецификация дизайн-системы приложения **YeetStyle (yeet)** — умного гардероба: пользователь оцифровывает свои вещи, получает образы на каждый день под погоду и повод, ищет похожие вещи по фото и общается с ИИ-стилистом.

> Статус: **v0.3**. Компоненты в Figma (страница 2.0) и в коде (Storybook) синхронизированы; экраны флоу в Figma ещё собраны на исходной коллекции. Разделы с пометкой _TBD_ будут дополняться.
>
> **Storybook** — живая документация для команды и руководства: правила, токены, компоненты, использование во флоу и <!-- gen:screens -->42<!-- /gen:screens --> экранов. Публикуется в GitHub Pages workflow-ом `.github/workflows/storybook.yml`; локально — `npm ci && npm run storybook`.
>
> **Значения токенов в этом файле генерируются** из `tokens/tokens.json` (`npm run docs-tokens`, проверка — `npm run docs-tokens -- --check`): блоки между `<!-- gen:… -->` руками не правятся. Канонические описания — страницы Storybook (MDX) и `src/docs/registry.ts`; этот файл со временем сожмётся до указателя на них.

## 2. Принципы

1. **Одежда — главный герой.** Интерфейс белый и тихий; цвет и фактура приходят из фотографий вещей. Вещи всегда на светло-сером `light-grey` фоне без собственного фона (фон удаляется при съёмке).
2. **Один акцент.** Насыщенный синий `#0100F4` — единственный брендовый цвет интерфейса: главное действие, выбранное состояние, активный фокус.
3. **Мягкая геометрия.** Всё интерактивное — «пилюли» (полное скругление); контейнеры — крупные скругления 20–32.
4. **Характерные заголовки.** Заголовки — засечковый Roboto Slab, весь остальной текст — Inter.
5. **Одна рука.** Основная навигация и действия — внизу экрана (плавающий таб-бар, FAB, bottom sheets).
6. **Разговорный и нейтральный тон.** Обращение на «ты», короткие живые фразы («Полный шкаф, а надеть нечего?»). Приложение для всех — тексты без привязки к полу (см. §8).

## 3. Токены

Имена токенов в коде должны повторять имена переменных Figma (с исправлением опечаток, см. §9).

Значения токенов живут в **`tokens/tokens.json`** — единый источник для web, iOS (SwiftUI) и Android (Compose); `npm run tokens` генерирует `src/tokens/tokens.generated.css`, `tokens/ios/YeetTokens.swift`, `tokens/android/YeetTokens.kt`. Нативная библиотека компонентов Android (Jetpack Compose) — `native/android` (см. её README); тот же `npm run tokens` генерирует для неё токены, иконки и шрифты.

В коде токены разложены на **три слоя** (`src/tokens/tokens.css`). Компоненты читают только семантический и компонентный слои — тема переключается одним атрибутом `data-theme="dark"`.

| Слой | Префикс | Пример | Кто использует |
|---|---|---|---|
| Примитивы | `--yeet-*` | `--yeet-blue-500`, `--yeet-graphite-900` | только слой семантики |
| Семантика | `--color-*`, `--space-*`, `--radius-*`, `--shadow-*` | `--color-bg-canvas`, `--color-text-secondary`, `--color-accent` | атомы, молекулы, организмы |
| Компонентные | `--button-*`, `--card-*`, `--sheet-*`, `--tab-bar-*`, `--input-*` | `--button-primary-bg`, `--sheet-radius` | конкретный компонент |

Соответствие Figma → код: `blue` → `--color-accent`, `black` → `--color-text-primary` / `--color-bg-inverse`, `grey` → `--color-text-secondary`, `light-grey` → `--color-bg-subtle`, `white` → `--color-bg-canvas`, `elevated` → `--color-bg-elevated`, `red` → `--color-danger`, `blue-text` → `--color-text-accent`, `red-text` → `--color-text-danger`, `on-accent` → `--color-text-on-accent`, `overlay` → `--color-bg-overlay`. Полная таблица со свотчами — Storybook → Foundations → Токены.

**Логика тёмной темы.** Токены названы по цвету светлой темы, а в тёмной работают по роли:
- `white` (фон) и `black` (текст) меняются местами; фон — не чистый чёрный, а графитовый `#0F0F11`, чтобы у фотографий вещей и карточек был воздух.
- `light-grey` → `#26262B` — карточки и поля читаются как слой над фоном; `elevated` (`#1A1A1E`) — таб-бар, sheet и диалоги отделяются от фона без обводок.
- Синий `accent` в тёмной теме осветлён (`blue-400`): исходный `#0100F4` на графитовом фоне почти не читается. Заливка при этом всё ещё ниже 4.5 : 1 к фону — поэтому **акцентный текст** на тёмном берёт отдельный, более светлый `text-accent` (`blue-200`), а не `accent`. Точные числа — в таблице контраста выше.
- `danger` одинаков в обеих темах (`red-600`), текст ошибок — отдельный `text-danger` (в тёмной светлее, `red-400`); подложки `accent-soft` и `danger-soft` в тёмной плотнее (20 % и 18 %), иначе пропадают.
- `accent-soft` в светлой теме — сплошной `#F1F4FF`, а не 10 % синего: на сером фоне прозрачная подложка темнеет.
- Кнопка **Black** в тёмной теме становится светлой (как «Sign in with Apple» на тёмном), snackbar — тоже инвертируется.
- Всё, что лежит на синем или красном, берёт `on-accent` (`text-on-accent`, `text-on-danger`), а не `white` — иначе в тёмной теме текст на синей кнопке стал бы тёмным.

### 3.7 Движение — `--motion-*`

Источник пяти переходов — страница Figma **Animations** (Smart Animate), остальные добавлены для жестов и выбора. В компонентах используются только семантические токены; пружины переведены в CSS `linear()` по пресетам Figma (mass 1). В Figma длительности лежат в переменных `motion/*` коллекции «Yeet DS 2.0» (скрыты из пикеров, code syntax `var(--motion-*)`), таблица — секция **11 · Motion**.

<!-- gen:motion -->
Переходов — 13.

| Токен | Кривая | Что происходит |
|---|---|---|
| `--motion-press` | 150 мс · standard | Нажатие кнопки, scale 0.97 |
| `--motion-fade` | 240 мс · standard | Затухание краёв, тосты |
| `--motion-collapse` | 300 мс · ease-out | Фото сворачивается в шапку при скролле |
| `--motion-page` | 300 мс · ease-out | Листание образов и поводов по свайпу |
| `--motion-nav` | 744 мс · spring quick (k300 c20) | Таб-бар уступает место FAB |
| `--motion-stamp` | 958 мс · spring bouncy (k600 c15) | Штамп «Надеть» → отмечено |
| `--motion-swap` | 1022 мс · spring gentle (k100 c15) | Смена образа: превью ↔ коллаж |
| `--motion-select` | 150 мс · standard | Выбор: фон чипса, вкладки, строки, цвет лайка |
| `--motion-lift` | 744 мс · spring quick (k300 c20) | Подъём под пальцем: вещь на холсте, карточка при перетаскивании |
| `--motion-drop` | 744 мс · spring quick (k300 c20) | Бросок в цель: вещь встаёт на место, соседи раздвигаются |
| `--motion-return` | 1022 мс · spring gentle (k100 c15) | Отмена перетаскивания: вещь возвращается туда, откуда взяли |
| `--motion-appear` | 240 мс · standard | Появление: snackbar, подсказка, диалог |
| `--motion-exit` | 150 мс · standard | Исчезновение: быстрее появления, чтобы не мешать |
<!-- /gen:motion -->

Кадры в Animations: `collapse` — new things; `page` — Stylist / Trips / List; `nav` — default → things (таб-бар 353 → 290, появляется FAB); `stamp` — dropdown → active button (штамп 148 → 78, −60°, «Надеть» → «×»); `swap` — scale (коллаж ↔ превью, штамп +180°).

Правила: пружина — ответ на действие пользователя; ease-out — движение, которое ведёт палец (не пружинит против руки); bouncy — только штамп. `prefers-reduced-motion` делает все переходы мгновенными.

Механики экранов (сводная таблица — Storybook «Анимации», источник `src/motion/motion.ts → mechanics`):
анимируются только transform / opacity; уход быстрее появления (`exit` 150 < `appear` 240); слои появляются
и уходят на `transition` + `@starting-style`, поэтому прерываются и разворачиваются из текущего положения.
`Overlay` с `onClose` — появление, уход, смахивание (порог 30 % / 500 pt/с, резинка 0.55, хаптика `threshold`);
`Screen` доигрывает уход убранных `overlay` и `floating` (`usePresence`); `Snackbar autoHide` — 4 / 6 с с паузой
под курсором и фокусом. Хаптика вызывается в компонентах через `haptic('<событие>')` (`src/utils/haptic.ts`),
числа жестов — из `tokens.json` (`src/utils/gesture.ts`), а не константами в коде.

**Штамп (`stamp` / `<Stamp>`)** — фирменная 12-лучевая звезда главного действия поверх коллажа: Primary L 148 («Надеть», «Сохранить»), Secondary 64 (белая иконка 29 с наклоном −15°, «Не нравится»). В Figma — интерактивный компонент: клик переключает `State=Default ↔ Done` через Smart Animate Bouncy.

**Тап-зона.** Визуально кнопка может быть 40, но зона нажатия — минимум 44 pt на iOS и 48 dp на Android. Недостающее добирается невидимым hit-slop вокруг кнопки: размер и отступы в макете не меняются, соседние зоны не перекрываются. iOS — `.yeetHitArea(height: 40)` из `native/ios` (это `.contentShape(Rectangle().inset(by: −2))`: форма нажатия выходит за края без изменения раскладки) или, если место позволяет, `.frame(minWidth: 44, minHeight: 44)` + `.contentShape(Rectangle())`; Android — `Modifier.minimumInteractiveComponentSize()` (Material 3 добирает зону до 48 dp, не меняя видимый размер); web — прозрачный `::before` с отрицательным `inset` до 44 × 44. Подробно — Storybook → «Процессы / iOS и Android».

Правило: экран = `header` сверху + скроллящийся контент + `bottom-nav` или `bottom-bar` снизу. Всё временное (действия, фильтры, выбор) открывается **bottom sheet'ом**, а не новым экраном.

### Скролл и края экрана

- Шапка и нижняя навигация **закреплены**, контент скроллится **под ними**.
- Под `header` — сплошная подложка `white` + полоса затухания 24 (`scroll-edge` Top); над `bottom-nav` — затухание 40, над `bottom-bar` — 24 (`scroll-edge` Bottom). Всё уже встроено в компоненты.
- Затухание сделано альфа-маской поверх `ui-colors/white`, поэтому одинаково работает в светлой и тёмной теме. Не рисовать градиенты вручную фиксированным белым.
- Контент в покое начинается под шапкой (≈ высота `header` − 16) и заканчивается над нижней навигацией (нижний отступ списка ≥ высоты `bottom-nav`).
- Плавающие элементы (tab-bar, FAB, «Показать ещё», hint) — эффект-стиль `shadow/floating`.

### Фото вещей без фона (вырезки ИИ)

После удаления фона у фото разные холсты, поля и «масса» (худи занимает 90 % кадра, кепка 10 %, у сумки ручка сверху). Вписывать целиком (`contain`) нельзя — вещи в сетке прыгают. Правило `src/utils/artBalance.ts` (чистые функции, так же в iOS / Android):

1. **Измерить один раз при загрузке вещи** (`measureArt` / `measureAlpha` по RGBA): рамка непрозрачных пикселей (альфа > 8 — без ореола), плотность силуэта, центр масс. Хранить `ArtMeta` рядом с фото (доли холста, от разрешения не зависят). Без метаданных фото меряется в браузере при первом показе.
2. **Визуальный вес, а не габарит**: масштаб по √площади силуэта → `target × вес категории`. Рамка не больше `maxFill` ячейки.
   | Контекст | Ячейка | target | maxFill | верх · верхняя · низ · обувь · аксессуары · сумка |
   |---|---|---|---|---|
   | `card` (сетка, поиск, фото-область) | 173 (фото-область 353) | 0.62 | 0.8 (поля ≥ 17) | 1 · 1.04 · 1 · 0.74 · 0.66 · 0.86 |
   | `collage` (образ) | из раскладки | 0.78 | 1 | 1 · 1.12 · 1.04 · 0.62 · 0.5 · 0.72 |
3. **Оптический центр**: рамка по центру ячейки, затем сдвиг к центру масс на 50 %, не больше 6 % ячейки.
4. **Коллаж без ручных координат** (`layoutCollage`, вещи без `x`/`y`): колонки «верхняя одежда · верх+низ · аксессуары/сумка/обувь» (верхняя одежда отдельно, только если есть и верх), внутри — сверху вниз; зазор 12 между силуэтами по обеим осям; композиция по центру площадки с полями 24, под бейджем повода 60, над панелью цены 92; не влезает — уменьшается целиком, одна-две вещи укрупняются до ×1.25.

Демо: Storybook → Organisms / PhotoBalance (до / после, коллаж, измерение).

## 6. Компоненты

Система построена по **Atomic Design**: токены → атомы → молекулы → организмы → шаблоны → страницы. Правило зависимостей — только вниз: атом не знает о молекуле, организм не импортирует страницу.

| Уровень | Что это | В коде (`src/`) | В Figma |
|---|---|---|---|
| Tokens | цвет, шрифт, отступ, радиус, тень | `tokens/` | коллекция «Yeet DS 2.0», стили |
| Atoms | неделимые элементы | `atoms/` — Icon, Logo, Button, IconButton, Stamp, Badge, Avatar, ColorDot, Divider, Text, ScrollEdge | 01–02 |
| Molecules | связка атомов с одной задачей | `molecules/` — Field, InputGroup, InputBar, SegmentControl, ChipGroup, ListItem, ListGroup, StatTile, Note, Hint, Snackbar, EmptyState, LoadingState, PhotoTile, Carousel, BarChart, UsageMeter | 03–04, 07–08 |
| Organisms | самостоятельный блок экрана | `organisms/` — Header, TabBar, BottomNav, BottomBar, Sheet, Dialog, карточки (Item, Product, Trip, StylistPrompt), OutfitCollage, OutfitThumbnail, PhotoArea, ChatBubble | 05–07 |
| Templates | каркас экрана без данных, скролл и края | `templates/` — Screen, Grid, Row | 10 Screen patterns |
| Pages | экран флоу с реальными текстами | `pages/` | New app design |

**Контекст в компонентах.** Компонент описывает, *где* он живёт во флоу: в Figma — фреймы `usage / <component>` справа от компонента, в Storybook — история «В флоу» с названием экрана. Варианты выбираются по роли в контексте (например, `Header` = Large на корневых вкладках, Back на вложенных, Search в поиске), а не по вкусу.


### 6.1 Атомы

- **Цвета аккаунтов:** фон — цвет из `tokens.avatar.palette` (синий, оранжевый, зелёный, фиолетовый, розовый, красный, жёлтый, коричневый, чёрный), буква — `on`-цвет этого цвета (`--yeet-on-item-*`): чёрная или белая, у кого контраст выше, все ≥ 4.5 : 1. Белый, бежевый и серый не используются. Без явного цвета он выбирается по id аккаунта. Есть фото — показывается фото.
- Один аккаунт: в шапке аватар + «+», в шторке — Current и «Добавить аккаунт». Несколько: все аватары, в шторке Current, затем Other.

## 7. Флоу приложения (контекст)

Фреймы в Figma называются по схеме **`Раздел / Экран / Состояние`**, напр. `Wardrobe / Items / Empty`, `Auth / Sign In / Password Visible`. Оверлеи: `… / Sheet / …`, `… / Dialog / …`, `… / Toast / …`. Эту же схему используем для имён экранов, превью и сторибуков.

| Раздел | Экраны |
|---|---|
| **App / Onboarding** | Splash (синий фон, вордмарк) → Welcome («Полный шкаф, а надеть нечего?») → Name → First Item (фото + автоудаление фона) → First Outfit |
| **Auth** | Sign In (email/пароль, Sign in with Apple), Password Recovery |
| **Outfits (Сегодня)** | Образ дня под погоду (Sunny / Rain Alert), выбор повода, действие «Надеть», пустое состояние |
| **Search** | По тексту и по фото (кроп), результаты, фильтры цены и сортировки, «Нет результатов» |
| **Wardrobe** | Вещи / Образы / Вишлист, фильтры (категория, сезон, теги, повод), карточка вещи и образа, редактирование |
| **New Item** | Фото → удаление фона → детали (название, категория, цвет, сезон) |
| **Outfit Creation** | Критерии → выбор вещей → холст (жесты, фильтры) → сохранение |
| **Wishlist, Archive, Trash** | Списки, действия, перемещение между ними, очистка |
| **Stylist** | Чат с ИИ-стилистом, каталог, «Образ дня», поездки (Trips) |
| **Profile / Settings** | Аналитика гардероба, редактирование профиля (аватар, пол, стиль, год рождения), страна и валюта, выход, удаление аккаунта, Legal |

Каждый экран проектируется во всех состояниях: **Default / Populated, Empty, No Results, Focused, Filled, Loading**.

## 8. Контент и тон

Приложением пользуются и девушки, и парни — **тексты гендерно-нейтральные**.

- Язык интерфейса — русский, обращение на **«ты»**.
- **Никаких родовых окончаний** в глаголах прошедшего времени и прилагательных, обращённых к пользователю. Перестраиваем фразу через настоящее/будущее время, инфинитив, вопрос или существительное:

  | ✗ Не так | ✓ Так |
  |---|---|
  | Забыла пароль? / Забыл(а) пароль? | Не помнишь пароль? |
  | Увидела в соцсетях — найди такую же | Нашёлся образ в соцсетях? Найдём похожее дешевле |
  | Ты готова? | Всё готово? / Начнём? |
  | Рады, что ты с нами, дорогая | Рады, что ты с нами |
  | Ты сохранила образ | Образ сохранён |

- Никаких «(а)», «/а» и прочих скобочных форм — только перестройка фразы.
- Примеры в макетах (имена, почта, одежда) — вперемешку: разные имена, мужские и женские вещи.
- Выбор пола в профиле — `Женский / Мужской / Унисекс`, но **тексты интерфейса от этого выбора не зависят**; пол влияет только на подбор вещей и образов.
- Заголовки короткие и живые, могут быть вопросом («Точно хочешь выйти?», «Очистить корзину?»).
- В диалоге описание объясняет последствия («Все вещи из корзины удаляются навсегда, их уже не вернуть»).
- Текст кнопки — глагол действия («Сохранить и выйти», «Применить», «Надеть»), а не «ОК/Да».
