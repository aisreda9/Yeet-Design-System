# Как вносить изменения

Кто что меняет и как не мешать друг другу — [`TEAM.md`](./TEAM.md) (зоны — `.github/team.json`, владельцы — `.github/CODEOWNERS`).
Этот файл — **как** сделать изменение правильно: новый компонент, правка существующего, PR.

## Главное правило

**Компонент DS — закон, экран — пример использования.** Правка идёт по цепочке
Figma → реестр → код → история «В флоу» → QA → эталоны, и ни один шаг не пропускается молча:
если шага нет (например, в Figma ещё нет компонента) — это пишется в реестре (`figmaWhy`, `statusWhy`), а статус не поднимается до `stable`.

## Новый компонент

1. **Figma.** Компонент на странице Design System 2.0 (Claude) `942:5666`, в своей секции (01–10), на переменных «Yeet DS 2.0», с вариантами и описанием; справа — «В флоу» с реальными текстами экранов.
   Писать в Figma — только держа замок в issue «Координация» (#6), см. `TEAM.md` §5. Нет Figma-компонента и замка — переходи к шагу 2 с `figmaId: null` и причиной.
2. **Реестр.** Строка в `src/docs/registry.ts` — **добавлением в конец своего блока**, чужие строки не трогать:
   `code`, `figma`, `figmaId` (или `null` + `figmaWhy`), `level`, `section`, `story`, `status` (+ `statusWhy`).
   Строка сразу появится на «Атомарной карте», в таблице «Старт / Процессы / Figma ↔ код» и бейджем в сайдбаре.
3. **Код.** Свой файл в папке уровня (`src/molecules/account.tsx`), экспорт — точечной строкой в `index.tsx` слоя.
   Импорт только из уровней ниже. В стилях — только семантические и компонентные токены (`--color-*`, `--button-*`), без hex и примитивов.
   Имена пропсов = свойства Figma по смыслу, варианты — в нижнем регистре (`variant="primary"`, `size="L"`).
4. **История.** `src/<уровень>/<Компонент>.stories.tsx`, `title: '<Уровень>/<Компонент>'` (тот же, что `story` в реестре):
   Playground, все варианты и **«В флоу»** — компонент в экранах с реальными текстами. Светлая и тёмная тема, 320 и 430 (тулбар «Экран»).
   Интерактивный компонент (кнопка, поле, группа выбора, оверлей, навигация) — ещё история **«Клавиатура»** с `play`: Tab, Enter / пробел, стрелки, состояние через роли и `aria-*` (правила — `design/QA.md`, «Play-тесты»). `npm run test-storybook` — зелёный.
5. **QA.** `npm run build-storybook && npm run qa` — 0 ошибок. Замеры Figma — в `design/figma-specs.json` (зона qa: попроси в issue, если не твоя).
   Экраны — `npm run flow-diff`.
6. **Эталоны.** `npm run qa -- --update-baseline`, `qa/baseline/*.png` — в том же PR (снимается в закреплённом образе, [ADR 0005](./design/adr/0005-qa-baselines-pinned-image.md)).
7. **Статус.** Поставь по факту ([ADR 0007](./design/adr/0007-component-status.md)):

   | Статус | Когда |
   |---|---|
   | `stable` | Figma-компонент + код + «В флоу» + используется на экранах + эталоны QA |
   | `beta` | на экранах и под QA, но нет Figma-компонента или «В флоу» |
   | `alpha` | ещё не на экранах или без Figma |
   | `deprecated` | не использовать; замена — в `statusWhy` |

## Правка существующего компонента

- Меняется вид — сначала Figma (под замком), потом код, эталоны перегенерировать в том же PR.
- Меняется API — поправить все места использования и истории; у `beta` / `stable` — описать в PR, что сломается у потребителей.
- Добавил «В флоу», Figma-компонент или вывел на экран — подними `status` в реестре.
- Компонент заменён — `status: 'deprecated'` и чем заменить в `statusWhy`; удалять строку — когда компонент перестал экспортироваться.

## Токены

Только в `tokens/tokens.json`, затем `npm run tokens` (CSS, Swift, Kotlin) и `npm run docs-tokens` (таблицы в `DESIGN.md`).
Сгенерированные файлы руками не правятся. Меняет значения только роль «Токены и платформы».

## Решения

Решение, которое меняет правило для многих компонентов или которое будут оспаривать, — ADR в `design/adr/` по [шаблону](./design/adr/0000-template.md).
Журнал в чате или в описании PR решением не считается.

## Документация

- Каноничны MDX (`src/docs/*.mdx`), истории и `registry.ts`. `DESIGN.md` — указатель, в нём не дублируем MDX.
- Тексты интерфейса — на «ты», без родовых окончаний (Storybook «Foundations / Тексты и тон»).

## Чек-лист PR

Шаблон — `.github/pull_request_template.md`. Перед переводом в Ready:

- [ ] Задача в issue, отметка `🔒 Беру` с ролью, веткой и зонами; PR с `Closes #…`
- [ ] Правки только в своих зонах; горячие файлы (`registry.ts`, `index.tsx`, `*.css`, `DESIGN.md`, `tokens.json`, `package*.json`) — точечными добавлениями
- [ ] `git fetch origin && git merge origin/main` (не rebase запушенной ветки)
- [ ] `npm run typecheck`
- [ ] `npm run build-storybook && npm run qa` — 0 ошибок; экраны — `npm run flow-diff`; токены — `npm run contrast`, `npm run docs-tokens -- --check`
- [ ] `npm run test-storybook` — зелёный; у нового / изменённого интерактивного компонента есть история «Клавиатура» с `play`
- [ ] Новый / изменённый компонент: строка в реестре со статусом, история «В флоу», эталоны в PR
- [ ] Figma: не писал / писал под замком и снял его
- [ ] Раздел «Передача» заполнен: что сделано, что нет, что дальше
- [ ] CI `QA Storybook` зелёный; мерж — координатор (порядок: токены → атомы → молекулы → организмы → экраны → документация)
