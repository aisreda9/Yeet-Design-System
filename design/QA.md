# QA: как доводим Storybook до уровня Figma

## Команда

```bash
npm run build-storybook && npm run qa     # отчёт: qa/out/report.md, скриншоты: qa/out/screens
npm run qa -- --only=organisms-header     # одна группа историй
npm run qa -- --update-baseline           # принять текущие скриншоты как эталон (qa/baseline, коммитится в git)
npm run qa -- --no-docker                 # без Docker: всё, кроме сравнения скриншотов
npm run qa -- --tap-min=40                # порог зоны нажатия для предупреждения (по умолчанию 44)
npm run contrast                          # контраст токенов; --all — все пары, --brands=error — бренды как ошибка
npm run flow-diff                         # экраны против флоу Figma: qa/out/flow-diff.md
node scripts/qa/boxes.mjs <экран> [селектор] # координаты блоков экрана для ручной сверки
node scripts/qa/shots-pages.mjs s320        # все экраны на 320 (s320, a360, s375, i393, m430) → qa/out/pages-s320
node scripts/qa/sheet.mjs qa/out/pages-s320 qa/out/s320.png   # сводный лист для просмотра
```

`flow-diff` берёт текстовые якоря из `design/figma-flows.json` (23 экрана страницы New app design: текст, x, y, кегль, шрифт, цвет) и ищет их на экранах `Pages/Экраны флоу`. Допуск 2 px; по горизонтали сравнивается лучший из левого края, центра и правого края (выравнивание в Figma неизвестно). Осознанные расхождения лежат в `known` с причиной и в счёт ошибок не идут. Якоря обновляются выгрузкой из Figma при изменении макетов.

### Визуальная регрессия: эталоны в git, скриншоты в закреплённом образе

Пиксели зависят от сборки Chromium, шрифтов и библиотек ОС, поэтому эталоны снимаются и сравниваются только в одном окружении —
образе `mcr.microsoft.com/playwright` той же версии, что `playwright-core` (тег и digest — `IMAGE` в `scripts/qa/lib.mjs`).
`npm run qa` сам перезапускается в этом образе через Docker (репозиторий монтируется в `/work`), локально и в CI одинаково.

- **Изменил вид компонента намеренно** → `npm run build-storybook && npm run qa -- --update-baseline`, закоммитить `qa/baseline/*.png`
  вместе с правкой. В PR ревьюер видит старый и новый PNG рядом — это и есть визуальное ревью.
- **Новая история без эталона** — ошибка «нет эталона»; **эталон удалённой истории** — «лишний эталон». Лечится тем же `--update-baseline`.
- **Конфликт в `qa/baseline/*.png` при мерже** — взять любую сторону и перегенерировать эталоны на смёрженной ветке.
- **Нет Docker** (локально) — скриншоты не сравниваются, в отчёте это написано явно. В CI без Docker — ошибка, а не «0 расхождений».
- **Обновили `playwright-core`** — поменять `IMAGE` (тег и digest: `docker pull … && docker inspect --format '{{index .RepoDigests 0}}'`)
  и перегенерировать все эталоны. Несовпадение версий скрипт ловит сам.
- Порог: любой пиксель, отличающийся сильнее pixelmatch threshold 0,1 (сглаживание не считается), или другой размер снимка; `--diff-px=N` — допуск. В закреплённом образе повторный снимок совпадает побайтно, а относительный порог 0,1 % пропускал сдвиг иконки на 2 px в больших витринах. Разница — в `qa/out/diff`, свежие снимки — в `qa/out/screens`.

### Контраст (`npm run contrast`)

Пары не перечисляются руками, а собираются из `tokens/tokens.json` для базовой темы и каждого бренда × светлая / тёмная:

- **текст 4,5 : 1** — каждая пара `component.*-fg` × `*-bg`, каждый `text-*` на `bg-canvas` / `bg-elevated` / `bg-subtle`
  (у `text-inverse*`, `text-on-*` — своя подложка), `text-accent` на `accent-soft`;
- **не-текст 3 : 1** (WCAG 1.4.11) — фокус-кольцо и индикатор выбранного на всех поверхностях. Фокус проверяется по токену
  `focus-ring`, а пока его нет — по `accent` (скрипт пишет об этом);
- полупрозрачный фон кладётся на каждую поверхность, берётся худший случай;
- **бренды — эксперимент** (решение 28.09): их провалы — предупреждение, `--brands=error` делает их ошибкой;
- известные нарушения базовой темы — `KNOWN` в скрипте со ссылкой на issue; когда пара начинает проходить, скрипт требует убрать запись.

В CI то же самое делает `.github/workflows/qa.yml` на каждый push и PR: отчёт появляется в Summary запуска, скриншоты лежат в артефакте `qa-report`.

## Что проверяется (каждая история × светлая и тёмная тема)

| Проверка | Уровень | Что ловит |
|---|---|---|
| История упала / пустая, ошибка JS, `console.error`, HTTP 4xx | ошибка | Сломанные истории и контролы |
| Спека Figma (`design/figma-specs.json`, допуск 1 px) | ошибка | Размеры, паддинги, gap, радиусы, шрифты |
| Тень перекрыта | ошибка | Позиционированный сосед закрывает тень (баг ScrollEdge над таб-баром) |
| Тень обрезана | ошибка / предупр. | `overflow` предка режет тень |
| Текст вылез | ошибка | Длинные подписи вылезают из блока |
| За краем экрана | ошибка | Элемент шире экрана 393 и не в скролле |
| Зона нажатия | ошибка < 24, предупр. < 44 (`--tap-min`) | Мелкие кнопки. Учитывается невидимое расширение `::after`. В нативе — 44 pt (iOS) и 48 dp (Android) |
| axe-core | critical и serious — ошибка, остальное — предупр. | Кнопки без названия, вложенные кнопки, контраст |
| Скриншот против `qa/baseline` (в git) | ошибка: любой отличающийся пиксель, другой размер, нет эталона | Регрессии после рефакторинга. Только в закреплённом образе — см. выше |
| Экраны на 320 и 430 | как выше | Резиновая вёрстка: вылезание за край, текст, зоны нажатия (`--no-devices` — пропустить) |

Найденное нарушение, которое чинит другая задача, заносится в `KNOWN` в `scripts/qa/run.mjs` (`проверка|история` → ссылка на issue): в отчёте оно в разделе «Известные нарушения» и CI не валит. Когда нарушение исчезает, запись становится ошибкой «устаревшее исключение», так что исключения не переживают починку.

## Цикл (1 итерация ≈ 1 день)

1. **Аудит.** `npm run qa`, а также сверка с Figma: `get_design_context` и скриншоты компонентов со страницы Design System 2.0.
2. **Разбор.** Каждая находка — баг кода, неточность спеки или решение дизайна. Решения дизайна (контраст, размер зон нажатия) выносятся дизайнеру, код их не меняет.
3. **Пачка правок.** Сначала общие причины (layout, токены), потом частные.
4. **Повторный прогон.** 0 ошибок — иначе обратно к шагу 3.
5. **Ревью глазами.** Скриншоты светлой и тёмной темы рядом с Figma.
6. **Эталон.** `--update-baseline`, после этого любое изменение пикселей = осознанное.

## Критерии «почти идеально»

- 0 ошибок в `npm run qa`, 100 % спек Figma в пределах 1 px.
- Все компоненты из `src/docs/registry.ts` покрыты спекой (сейчас 47 замеров).
- 0 нарушений axe уровня serious и выше, контраст AA для текста (решение по токенам — ниже).
- Скриншоты стабильны: в закреплённом образе снимок совпадает с эталоном до пикселя.
- Нативная проверка: те же экраны на iPhone 15 и Pixel 8 (шрифты, safe area, Dynamic Type / font scale 1.3).

## Решено по контрасту (итерация 1)

- `text-secondary` → `#6E6E6E` (4,85 : 1 на белом, 4,53 : 1 на `#F7F7F7`).
- `danger` (заливка) → `#CC291B`: белый текст бейджа 5,4 : 1. `text-danger` в тёмной теме — `#FF6B5C`.
- Тёмная тема: `accent` → `#4B4BFF` (белый текст 5,6 : 1), `text-accent` → `#8A8AFF`.
- В Figma текст отделён от заливок: `ui-colors/blue-text`, `ui-colors/red-text`.
- Кнопки больше не сжимаются по высоте во flex-колонке (`fullWidth` делит место только в рядах).

Осталось на решение: строки `list-item` 24 px и кнопки S 32 px — в нативе расширять зону нажатия, не меняя вид.
