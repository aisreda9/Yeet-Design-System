# 0007. Статус зрелости компонента в реестре

- **Статус:** принято
- **Дата:** 2026-09-29
- **Где обсуждали:** #62 (фаза 6 `design/AUDIT.md`)
- **Затрагивает:** docs (`src/docs/registry.ts`, `status.ts`, `20-Figma.mdx`), `.storybook/manager.ts`

## Контекст

Реестр связывал Figma и код, но не говорил, можно ли брать компонент в продукт: часть уже на экранах и под QA, часть — только в своей истории.

## Решение

У каждой строки `registry.ts` — `status` и, если не `stable`, `statusWhy` (чего не хватает):

| Статус | Критерий |
|---|---|
| `stable` | Figma-компонент (`figmaId`) + код + история «В флоу» + используется на экранах + эталоны QA |
| `beta` | на экранах и под QA, но нет Figma-компонента или истории «В флоу» |
| `alpha` | ещё не на экранах или без Figma; API может поменяться |
| `deprecated` | не использовать в новом коде; замена — в `statusWhy` |

Статус ставится по факту, а не по ощущению. Бейдж показывается в сайдбаре Storybook (у истории с несколькими компонентами — по самому незрелому из названных в заголовке) и в таблице «Процессы / Figma ↔ код».

## Последствия

- PR, который добавляет «В флоу», Figma-компонент или выводит компонент на экран, поднимает `status` в той же строке.
- `deprecated` не удаляется из реестра, пока компонент экспортируется.
