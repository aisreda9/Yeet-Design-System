# 0001. Зона нажатия 44 pt / 48 dp без изменения вида

- **Статус:** принято
- **Дата:** 2026-09-28
- **Где обсуждали:** `design/AUDIT.md` §3, решение 1; фаза 0
- **Затрагивает:** atoms, molecules, organisms, `native/`, `scripts/qa`

## Контекст

В макетах кнопки S — 40, строки `list-item` — 24, иконки в шапке — 40. Рекомендации платформ — 44 × 44 pt (iOS HIG) и 48 × 48 dp (Material).
Увеличивать видимые размеры — значит расходиться с Figma.

## Решение

Визуальные размеры не меняются. Зона нажатия дотягивается до **44 pt на iOS** и **48 dp на Android** невидимым hit-slop вокруг элемента;
соседние зоны не перекрываются — если перекрываются, раздвигаются элементы, а не уменьшается зона.

- iOS — `.yeetHitArea(height: 40)` или `.frame(minWidth: 44, minHeight: 44)` + `.contentShape(Rectangle())`;
- Android — `Modifier.minimumInteractiveComponentSize()`;
- web — прозрачный `::before` / `::after` с отрицательным `inset` до 44 × 44.

## Последствия

- Правило и код для платформ — Storybook «Foundations / Отступы и радиусы» (`src/docs/12-Spacing.mdx`) и «Процессы / iOS и Android» (`21-Mobile.mdx`).
- `npm run qa` проверяет зону с учётом невидимого расширения: < 24 — ошибка, < 44 — предупреждение (`--tap-min`).
